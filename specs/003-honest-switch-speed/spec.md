# Spec 003 — честная скорость свитчей (flow-track)

## Жалоба
Кнопка отзывчивая (optimistic pill из 002), но факт тот же: ~10с reconnecting
при proxy↔smart. Уведомление «переключено» прилетает в момент нажатия.

## Замеры (живые, хост)
- toggle proxy/smart возвращается за 0.8–1.3с; сервис active в ту же секунду.
- Но status-json: 2.6с в покое, 4.6с в переходе (curl exit `-m 3` x2 таймаута +
  TCP latency-проба timeout 2 + питоны + sudo).
- Фазы тумблера суммарно 0.75с; sing-box слушает через 20мс, выход через 0.6с
  после чистого рестарта. Бэкенд быстрый — тормозили опросы + квантование
  (таймер 8с: готовность t+3 детектилась только на опросе t+10).
- TRANS_MARKER удалялся EXIT-трапом тумблера через 0.8с (TRANSITIONING не виден).

## Фикс (один общий путь для всех режимов)
- `singbox-toggle.sh`: exit-пробы `-m 3`→`-m 2` (`-m 1` дал ложный DEGRADED при
  egress 0.78с — замер), full-проба `-m 8`→`-m 3`, latency-проба timeout 2→1,
  гейты: нет tun → скип direct-curl, нет 10808 → скип socks-curl (неготовые
  опросы ~0.5с вместо 3.5с); маркер живёт до CONNECTED/OFF (deadlock 003c:
  сначала кандидат, потом оверрайд); сообщения «switching…» вместо «ON».
- GUI: burst-опросы 1.5с 12с после toggle (`_fast_poll_wanted`, pure fn);
  notify-send «Подключено» один раз на входе в CONNECTED (Popen, не блокирует).

## Результат
- status-json в покое: 2.6с → 0.75с.
- smart→proxy: CONNECTED с 1-го опроса, 3с. proxy→smart: 2с. Было ~10с.
- 17/17 pytest на хосте (3 новых: fast_poll, arm, notify-once).

## OUT
Редизайн пилюли, интервалы по умолчанию, fast-path статусы — не трогали.
